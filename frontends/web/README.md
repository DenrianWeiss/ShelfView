# Browser media components

`media-protocol.mjs` implements the bControl v1 media message format shared with
the C core. `media-worker.mjs` runs a read-only Blob/File source in a module Worker.
There is no browser filesystem path access and no whole-image upload.

`agent-media.mjs` now provides `publishFile({agentOrigin,token,file})`, which
negotiates a one-use source ticket, authenticates WebSocket and wires these
components together. It returns sourceId/channel, close() and a closed Promise.
The management page is available in `index.html`; its file picker publishes a
source and passes only `source_id` to the same Agent media mount endpoint.
The Agent adapts it to `bc_media_source` and serves bounded HTTP ranges for the BMC.
The Agent currently
negotiates a single in-flight read per source. See docs/media-channel.zh-CN.md.

After an application has selected a File and obtained a source/channel identity:

```js
const worker = new Worker(new URL('./media-worker.mjs', import.meta.url), { type: 'module' });
worker.postMessage({ type: 'open', sourceId, channel, file, maxBlock: 1048576, window: 8 });
// Incoming complete logical media messages are transferred to the Worker:
worker.postMessage({ type: 'frame', sourceId, frame }, [frame]);
// Send returned frame buffers on the authenticated source's binary channel.
// type=ready/error/closed are local Worker lifecycle events, not wire messages.
```

`sourceId` identifies the current generation at the Worker boundary. The channel
ID identifies it on the wire. A replacing generation must use a new identity.
The application must reassemble fragmented WebSocket messages before invoking
the codec; it must not assume a library frame callback is a logical message.

## Wire rules implemented

- Header: 40 bytes, magic BCTL, version 1, big endian, zero flags/reserved.
- READ: four-byte big-endian unsigned count, positive and at most negotiated block
  size. The offset/count must fit inside the actual selected file.
- DATA: exact requested bytes, same channel/request ID/offset as READ.
- ERROR: UTF-8 JSON error code. It is not a successful short DATA response.
- CANCEL/CLOSE: no payload. CANCEL suppresses a late response; CLOSE terminates
  the source. In-flight browser reads cannot be forcibly aborted by Blob APIs.
- Request IDs are nonzero and strictly increasing for READ within a generation;
  responses may complete out of order. Only the high-water mark is retained.
- Up to eight reads and 1 MiB per block; cancelled reads occupy their slot until
  the underlying browser read settles, preventing cancellation-based allocation
  growth.
- All wire 64-bit fields use BigInt. File.size must be a safe JavaScript integer
  before conversion; oversized requests are rejected before converting offsets
  to Number for Blob.slice().

Tests use real Node Blob and Worker implementations with a small browser-message
adapter, plus a frame generated by the compiled C encoder. This verifies the
components and transferred buffers, not browser permissions/rendering or a BMC.
Node is optional for core-only development; CMake adds the browser-media test when
Node is available, and it contains six subtests.

## KVM

`kvm-decoder.mjs` 提供通用解码入口，在独立 Worker 中加载 C 核心的 Wasm 构建；浏览器不再维护另一套 JavaScript RFB 解码器。Wasm 使用 `BC_KVM_DECODE_ONLY` 在编译阶段排除键鼠编码和控制台分类，只导出解码、显示读取及握手回复，不包含网络或管理模块。输入以 `{type:"input",event:{type:"key"|"pointer"|"scroll"|"chord",...}}` 文本消息发送至 Agent，由 C 核心编码；ticket 必须声明 `input_version:1`。认证后的 `ready` 消息携带核心 `input_capabilities` 位标记（bit 0 为滚轮）；缺少标记时不启用滚轮，查看器不按协议名称判断。指针和滚轮携带已显示画布的尺寸，组合键最多 8 个 keysym，并由核心逆序释放。

`kvm.html` + `kvm-page.mjs` 是最小页面：输入 Agent 地址与一次性配对秘密后，`agent-pair.mjs` 调用 `/v1/pair` 换取 token，再申请 KVM ticket、绘制 canvas、捕获键鼠。页面需从 Agent `--origin` 允许的源提供（否则浏览器 CORS/混合内容会拒绝），token 只保存在页面内存、秘密用后清空；页面刷新后需新的配对秘密。支持有限次退避重连，尚未实现多会话。

```js
import { connectKvm } from './agent-kvm.mjs';
const session = await connectKvm({
  agentOrigin, token,
  onFrame: ({ width, height, pixels }) => draw(width, height, pixels),
  onError: (reason) => console.error(reason),
});
```

## Agent management client

`agent-client.mjs` provides `AgentClient` for paired device connections, typed
queries, power commands and connection close. It reuses `agent-origin.mjs`;
credentials stay in memory and are sent only in the Authorization header.
Requests reject redirects and do not retry. Lost write responses report
`outcome_unknown`; `AgentError.result` preserves device status and task flags.

```js
import { AgentClient } from './agent-client.mjs';
const client = new AgentClient({ agentOrigin, token });
const { connection_id } = await client.connect();
try {
  const { members } = await client.query(connection_id, 'systems');
  const system = await client.query(connection_id, 'system', members[0]);
} finally {
  await client.close(connection_id);
}
```

The `agent-web-management` integration test runs this client against the compiled
Agent and a stateful HTTPS device fixture, verifying one session for system,
sensor, task and power operations, followed by logout. It does not validate
browser rendering or real device compatibility. The management page uses this client and serializes device operations.

## 本地化与键盘输入

`index.html` 和 `kvm.html` 的文案来自 `../i18n/catalog.json`（由 `sync.mjs`
生成 `i18n-catalog.mjs`），页面顶部语言下拉框切换中英并写入 `localStorage`；
静态节点用 `data-i18n`，动态文本用 `i18n.mjs` 的 `t()`，传感器单位/健康/状态
与任务状态通过同一词表映射，不直接把 Agent 的英文 token 当文案。

KVM 键盘按裸机键盘处理：使用 `KeyboardEvent.code` 的物理键映射到 US keysym，
不转发 IME 组合文本；输入法组合阶段（`isComposing`）的按键被忽略。

## Web 管理界面

`index.html` / `management-page.mjs` 提供一次性配对、设备会话、系统选择、
电源能力门控、传感器和任务手动刷新。秘密用后清空，token 仅在内存中；
断开会注销设备连接，再连接复用配对，“更换 Agent”清除页面配对状态。
刷新页面后需新的配对秘密；关闭浏览器标签不保证远端会话已注销。

KVM 页面需要先构建 Wasm 解码器。安装并激活官方 [Emscripten SDK](https://emscripten.org/docs/getting_started/downloads.html) 后，在仓库根目录运行：

```sh
python3 bindings/wasm/build.py
```

也可以给原生 CMake 配置增加 `-DBC_BUILD_WEB=ON`（必要时指定 `-DBC_EMCC_EXECUTABLE=/path/to/emcc`）。生成的 `frontends/web/generated/` 必须随静态页面一同部署，不能只复制 HTML/JavaScript 源码。构建后，`node --test frontends/web/tests/wasm-decoder.test.mjs frontends/web/tests/kvm-worker.test.mjs frontends/web/tests/agent-kvm.test.mjs` 检查核心解码与 Worker 绑定。

本地开发时分别启动静态前端和 Agent，前端源必须与 `--origin` 一致：

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory frontends/web
BC_BMC_USERNAME=user BC_BMC_PASSWORD=password build/bcontrol-agent serve \
  --pairing-file /private/tmp/bcontrol-pairing --port 8445 \
  --origin http://127.0.0.1:8765 --endpoint https://BMC_HOST --ca /path/to/ca.pem
```

浏览器打开 `http://127.0.0.1:8765`，输入 Agent 地址和新生成文件中的秘密。
HTTPS 部署须为 Agent 配置浏览器信任的证书，不能混用 HTTPS 页面和 HTTP Agent。
页面只列出设备声明支持的标准电源动作，并在执行前确认；命令接受、
任务待处理和实际电源状态分别显示，不自动重试写请求。
传感器无读数显示“—”，任务进度缺失不显示为 0%，部分读取失败保留已读条目。
KVM 查看器通过工具栏打开共用管理面板，独立管理页入口仍保留。共用面板支持远程 URL 镜像及浏览器本地 File 的挂载和弹出。
本地 File 入口只在 Agent 配置了 `--media-listen` 与 `--media-advertise` 时启用；advertise 地址须能被 BMC 访问。
文件在 Worker 中按设备请求读取，不整盘上传；关闭管理面板先卸载本地挂载，再关闭文件来源。


## KVM 与管理设备关联

确认 `--kvm-url` 与 `--endpoint` 指向同一台设备后，启动 Agent 时同时设置
`--device-id rack-1 --kvm-device-id rack-1`。标识支持 1–64 个英文字母、数字、
点、下划线和连字符；标识不一致或缺少任一地址时 Agent 拒绝启动。
这是操作者的明确关联声明，不是按主机名自动识别设备。

关联后，KVM ticket 返回 `management_device_id`，浏览器用此标识建立管理连接。
Agent 校验请求中的 `device_id`，连接响应也返回该标识；浏览器发现不匹配时
关闭连接并报告 `device_association_mismatch`。未关联的 KVM ticket 不包含管理设备标识。
旧的独立管理入口仍允许省略标识。查看器只在 ticket 提供关联标识时启用电源入口，
复用独立管理页的系统选择、电源和启动控制。关闭面板或断开 KVM 会等待在途操作后
注销管理连接；清理无法确认时禁用再次打开，避免继续占用未确认的设备会话。


媒体面板先读取 Managers 与 VirtualMedia 资源，再按核心返回的动作能力启用操作。
明确已插入或仍有镜像来源时禁止覆盖；旧 BMC 缺少 Inserted 且没有来源时允许尝试，
核心仍在提交前检查占用。当前配对客户端持有的挂载可通过该面板弹出，断开重连后由
Agent 恢复关联。Agent 弹出后读回状态，仍插入、来源残留或缺少状态时报告结果未知，
保留挂载记录以供后续清理。挂载请求接受后，面板也读回插入状态与镜像 URL，未匹配时
显示操作未确认；明确已插入但未提供 URL 时显示“来源未核实”。关闭面板、注销管理
连接、撤销配对或退出 Agent 会保留由 BMC 维持的 URL 远程挂载，本地媒体继续卸载。
远程归属使用 C 核心有界内存注册表，每个设备服务最多保留 8 条，每个管理连接当前
持有一条；同一配对客户端可通过多条连接管理不同槽位，不因为连接关闭或容量不足淘汰记录。Agent 重启后内存关联消失，后续恢复与
重启后可选中槽位显式弹出；其他活跃管理连接占用时拒绝接管，关闭后才允许操作。
借用已有记录失败不会改变原归属；读回空槽后清除记录。本轮未引入新的磁盘记录或修改 Vault。

本地 File 的挂载请求为 `POST /v1/connections/{id}/media`，包含 `media_uri`、
`source_id` 和 `write_protected:true`，与 `file`、`image_url` 互斥。来源必须由同一配对
客户端发布，且已经完成 WebSocket 认证；来源失效后不能被新挂载使用。Agent 为来源持有
有界租约，待 HTTP 读取结束才释放，旧来源不会因槽位复用变成新文件。
HTTP 来源支持单段闭合、开放结束及后缀 Range；起止和长度按 64 位检查。
来源断开或块读取超时时中止读取，Agent 随后关闭该来源关联的管理连接并尝试卸载本地媒体。
卸载未确认时继续显示未确认结果，不能将 Worker 关闭本身当作设备已经弹出。
